Disaster Recovery Plans

A practical guide for restoring important systems and keeping orders and shipping work organised when something goes wrong.

What Needs to Be Recovered First?

A Recovery Time Objective (RTO) is the target time to restore a service. A Recovery Point Objective (RPO) is the maximum planned period of recent data that may need to be recovered or re-entered.

The following are proposed targets, not results from actual recovery tests.

Service Proposed RTO Proposed RPO
Failed branch WAN link 1 hour Not applicable to transit traffic
Central DHCP and DNS 2 hours 24 hours of configuration changes
Core business database 4 hours for local failure / 8 hours for site loss 1 hour
Payroll 8 hours; review near payday 4 hours
Company working files 8 hours 4 hours
Customer website and staff portal 24 hours Last approved release

Recovery Procedures for Common Problems

Click a situation below to expand its response plan. These sections work using HTML and CSS only.

1. Power Failure at a Branch
  1. The branch lead checks staff safety and reports the outage.
  2. IT checks whether network equipment is supported by UPS power.
  3. Urgent orders are recorded manually if systems cannot be used.
  4. After power returns, IT verifies network access, order lookup and printing.
2. Internet or VPN Connection Failure
  1. IT checks router, firewall, VPN and service provider status.
  2. Switch to an approved secondary connection if available.
  3. Test the VPN, Cape Town business application and employee connectivity.
  4. Record the outage and return to the main link in a controlled window.
3. Cape Town Business Server Failure
  1. The specialist checks hardware and application status and keeps useful logs.
  2. Restore the latest validated backup to suitable hardware.
  3. If necessary, management may authorise the proposed Durban recovery host.
  4. Stock and finance employees check sample orders and data before reopening the service to everyone.
4. Ransomware or Account Compromise
  1. Disconnect affected devices and report the incident promptly.
  2. IT isolates compromised accounts and preserves investigation evidence.
  3. The specialist rebuilds and restores only from verified clean backups.
  4. The Information Officer and Legal Officer assess personal-information notification requirements.
5. Accidental Deletion or Damaged Records
  1. Report the missing or incorrect records and when they were last seen.
  2. Prevent further changes to affected data where necessary.
  3. Restore a backup to a separate test location first.
  4. The data owner checks the records and identifies transactions to re-enter.
6. Fire, Flooding or Loss of Cape Town Premises
  1. Follow the site evacuation procedure. Staff safety comes first.
  2. Senior management authorises alternate-site operation.
  3. Restore the key application using protected offsite backups and the proposed Durban recovery capacity.
  4. Branches test access, reconcile manual orders and report any gaps.
7. Lost Laptop or Stolen Login Details
  1. The employee phones IT with the device asset tag and last known time.
  2. IT disables access, revokes sessions and assesses possible information exposure.
  3. Prepare a replacement device only after identity verification.
  4. Record the loss and follow up on protective actions.
8. Customer Website or Staff Portal Unavailable
  1. Check the hosting, network and website files to locate the fault.
  2. Restore the previous approved static version if necessary.
  3. Test navigation links and verify published policy versions.
  4. Use an approved offline copy of policies until access returns.

Backups and Recovery Testing

Proposed Backup Approach

  • Keep production data, a separate local backup and protected offsite copies.
  • Use a supported database-consistent backup method and regularly test restores.
  • Save approved network configurations after changes.
  • Keep the current and two previous approved website releases.

Testing and Improvement

  • Monthly: Restore sample files or database records.
  • Quarterly: Test application recovery and branch WAN fallback.
  • Annually: Rehearse a full Cape Town site-loss scenario.
  • After Every Incident: Record actual times, problems and improvements.
Important: This page describes proposed disaster recovery plans. No real African Foods recovery test is claimed. Actual results must be recorded after practical testing and management approval.
